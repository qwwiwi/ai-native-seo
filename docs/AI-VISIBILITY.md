# Видимость в ответах нейросетей — как найти запросы, где вас не цитируют

Гайд для владельца сайта: как бесплатными инструментами поисковиков увидеть, по каким
запросам ваш сайт уже попадает в ответы нейросетей, а по каким — нет, и как превратить
пробелы в темы для новых материалов. Дополняет [`SEO.md`](SEO.md) (чем меряем поиск) и
[`CONTENT.md`](CONTENT.md) (откуда брать запросы). Опыт программирования и SEO не нужен.

> **Как читать.** Это новые функции: часть из них в статусе «preview» (предварительный
> доступ) или «beta» (пробная версия), и поисковики меняют их без предупреждения.
> Всё описанное ниже сверено с первоисточниками на **2026-11-13** (ссылки и даты — в конце).
> Что источники не подтвердили, помечено **«не подтверждено»** — проверяйте у себя в кабинете.

## Метод в трёх предложениях

Бесплатные **инструменты для веб-мастеров** (кабинеты, где поисковик показывает владельцу,
как его сайт виден в поиске) теперь показывают, по каким запросам сайт уже **цитируется в
ответах нейросетей** (то есть нейросеть берёт из вашей страницы факт и ставит на неё ссылку),
а по каким — нет. Запросы, где цитируют конкурентов, а вас нет, — это **пробелы**. Пробелы мы
добавляем в контент-план как целевые запросы для новых или усиленных материалов.

## Что показывает каждый инструмент

Коротко:

| Инструмент | Список запросов, где вас нет | Список запросов, где вы есть | Главное ограничение |
|---|---|---|---|
| Bing Webmaster Tools | да («Top Opportunity Queries») | да («Grounding Queries») | выборка, нужен минимум данных |
| Яндекс Вебмастер | частично (примеры запросов; **не подтверждено**, что туда попадают запросы без вас) | да (фильтр «Запросы с моим сайтом») | только запросы, где сайт уже высоко в обычном поиске |
| Google Search Console | нет | нет (только показы по страницам, странам, устройствам и датам) | нет списка запросов |

### Bing Webmaster Tools — «AI Performance» и «Topics Portfolio»

**Что это.** Bing Webmaster Tools — бесплатный кабинет поисковика Microsoft Bing. В нём есть
отчёт **AI Performance** (запущен в предварительном доступе 2026-02-10): он считает, как часто
ваши страницы цитируются в **Microsoft Copilot**, в AI-сводках внутри Bing и у «select partner
integrations» (выбранных партнёрских интеграций). ChatGPT в источнике по имени не назван —
входит ли он в эти партнёрские интеграции, **не подтверждено**.

**Где смотреть.** Войдите в Bing Webmaster Tools, выберите свой сайт и откройте раздел
**AI Performance**. Внутри — вкладка **Topics Portfolio (Beta)** (добавлена 2026-10-13).
Точный путь по меню в источниках не описан; ищите раздел по названию.

**Какие цифры есть в AI Performance:**

- **Total Citations** — сколько раз страницы сайта процитированы в AI-ответах за период;
- **Average Cited Pages** — сколько ваших страниц в среднем цитируется за день;
- **Grounding queries** — «ключевые фразы, которые ИИ использовал при поиске контента».
  Это не вопрос пользователя, а поисковая фраза, которую нейросеть сама составила для
  поиска источников;
- число цитирований по каждой странице;
- график по времени.

**Какие списки есть в Topics Portfolio:**

- таблица тем: **Topic** (тема), **Topic Size** (размер темы), **Sites Cited** (сколько сайтов
  цитируется), **Queries** (запросы);
- **Top Opportunity Queries** — «самые сильные запросы по всему вашему портфелю, где
  появляются другие сайты, а ваш нет». Это и есть список пробелов;
- на странице отдельной темы: **Your Grounding Queries** (где цитируют вас) и
  **Opportunity Queries** (где вас нет).

**Ограничения (из первоисточников):**

- данные — **выборка**: «показана часть общей активности цитирования»;
- вкладка Topics Portfolio появляется, только если по сайту **достаточно данных** — у
  небольших сайтов её может не быть;
- цифры приблизительные, объёмы по запросам-возможностям даны диапазонами;
- в «возможности» могут попасть брендовые запросы (названия компаний) — их отсеивайте;
- период просмотра — 1, 2 или 3 месяца;
- Bing сам просит относиться к цифрам как к «ориентирам для планирования, а не точной
  бухгалтерии».

**Не подтверждено** (в двух анонсах Bing этого нет, справку по отчёту открыть не удалось):
точный минимум данных; хранение истории дольше 3 месяцев; кнопка выгрузки в CSV (в том числе
в Topics Portfolio); API для этих отчётов; метки «намерения» запроса (что человек хочет:
узнать, купить, сравнить) — в анонсах они не упомянуты, так что намерение мы определяем
сами (см. ниже).

### Яндекс Вебмастер — «Видимость сайта в Алисе AI»

**Что это.** Отчёт про **Алису AI** — нейроответы Яндекса. Показывает, насколько часто сайт
упоминается в её ответах.

**Где смотреть.** Яндекс Вебмастер → ваш сайт → **Эффективность** → **«Видимость сайта в
Алисе AI»** (адрес вида `webmaster.yandex.ru/site/efficiency/alice/`).

**Что показывает:**

- переключатель популярности запросов: топ-3, топ-10, топ-20;
- **«Динамика Share of Voice»** — доля запросов, на которые ответила Алиса, где упоминается
  ваш сайт (share of voice — «доля голоса»);
- **«Примеры → Запросы и страницы»** — несколько популярных запросов и страницы, которые
  Алиса процитировала;
- **«Примеры → Сайты»** — сайты, которые часто цитируются по тем же запросам (это ваши
  конкуренты в ответах нейросети);
- фильтр **«Запросы с моим сайтом»**.

**Ограничения (из справки Яндекса):**

- учитываются только запросы, по которым сайт **уже высоко в обычном поиске**; если вас нет
  в обычной выдаче, в отчёте вы тоже не появитесь;
- нет кликов и показов — только доля упоминаний;
- история — 3 месяца, обновление раз в неделю;
- у небольших сайтов показывается «Пока недостаточно данных».

**Не подтверждено:** что в списке запросов по умолчанию есть запросы, где вас **не**
цитируют (так можно предположить по названию фильтра, но справка этого не говорит); год
анонса отчёта (на странице стоит «7 апреля», 2026 выведен по подвалу страницы); есть ли
выгрузка именно этого отчёта (у Вебмастера выгрузка списка запросов в интерфейсе есть, но
для отчёта про Алису проверьте сами).

### Google Search Console — отчёты Generative AI performance

**Что это.** Google Search Console — бесплатный кабинет Google. С 2026-06-03 в нём
анонсированы отчёты **«Search Generative AI performance»**: отдельно для Поиска (AI Overviews
и AI Mode — нейроответы Google) и отдельно для Discover (ленты рекомендаций). По заметке к
анонсу, на всех сайтах они появились 2026-08-31.

**Что показывают:** только **показы** (сколько раз сайт показан в AI-ответах), в разрезе
страниц, стран, устройств и дат.

**Ограничения:**

- **списка запросов нет**: в анонсе запросы не названы среди разрезов, и там ничего нет про
  запросы, где вашего сайта нет. Это основано на молчании анонса, отдельной справки по отчёту
  найти не удалось — **не подтверждено**;
- по старой документации Google, показы в AI-функциях учитываются в обычном отчёте
  «Эффективность» внутри типа поиска «Веб» и отдельно от остальных не выделяются;
- приложение Gemini в анонсе не упомянуто — **не подтверждено**, что оно покрыто;
- точный пункт меню в источниках не указан — **не подтверждено**, ищите по названию отчёта.

Вывод для метода: Google не даёт пробелов по запросам. Он нужен, чтобы видеть, **какие
страницы** уже попадают в AI-ответы, и сверять это с данными Bing и Яндекса.

## Что на самом деле значит «87%»

В пересказах метода часто звучит: «87% ответов ChatGPT берут источники из топ-20 Bing».
Это неточно. Исследование — Seer Interactive, «87% of SearchGPT Citations Match Bing's Top
Results», опубликовано 2025-02-06. Что в нём измерено:

- **цитаты, а не ответы**: у ответов, в которых нейросеть искала в вебе, взяли ссылки-источники;
- выборка маленькая: около 100 вопросов и больше 500 цитат; только вопросы, которые
  запускали веб-поиск;
- **87% процитированных адресов точно совпали с адресом из топ-20 органической выдачи Bing**
  по тому же вопросу; для Google — 56%.

Ограничения, которые указали сами авторы: выборка «ориентировочная»; большинство вопросов
содержали «top» или «best», поэтому результат смещён к партнёрским сайтам и агрегаторам;
ChatGPT мог переписать вопрос перед поиском; часть цитат из Википедии не совпала.

От себя: исследованию 21 месяц, и оно про ранний SearchGPT, поэтому **не подтверждено**,
что сегодняшний ChatGPT ведёт себя так же.

**Честный вывод.** Видимость в Bing — разумный и дешёвый сигнал: данные бесплатные, отчёт
прямо показывает пробелы. Но это не гарантия присутствия в ChatGPT. Используйте Bing как
подсказку, какие темы закрыть, а не как обещание результата.

## Первая настройка — один раз

Сначала выберите, с чего начать. Если у вас нет ни одного кабинета — начните с Bing: это
самый простой шаг, и только Bing показывает пробелы списком.

### 1. Bing Webmaster Tools (нужно завести)

1. Откройте `bing.com/webmasters` и войдите аккаунтом Microsoft, Google или Facebook.
2. Добавьте **ваш сайт** и подтвердите, что он ваш (это называется «верификация»), любым из
   способов: запись в DNS (настройках домена), файл на сайте или мета-тег в коде страницы.
3. Для ручной работы (смотреть отчёты глазами) шагов больше не нужно. Если планируете
   подключать скрипты: Settings → API Access, примите условия (прочитайте их) и создайте
   API-ключ. Ключ — это пароль: храните в менеджере паролей, не кладите в репозиторий и не
   отправляйте в чаты.
4. Подождите. Данных сначала нет, а Topics Portfolio появляется, только когда их
   достаточно.

### 2. Яндекс Вебмастер

1. Если сайт ещё не добавлен — добавьте его и подтвердите права.
2. Откройте Эффективность → «Видимость сайта в Алисе AI».
3. Посмотрите: видны данные или надпись «Пока недостаточно данных». Второе — нормально для
   нового или небольшого сайта; вернитесь через неделю-две.

### 3. Google Search Console

1. Если сайта нет — добавьте **ресурс типа «Домен»** и подтвердите его записью DNS TXT.
2. Откройте отчёт Generative AI performance и убедитесь, что в нём есть данные.
3. Доступ скриптам (сервисному аккаунту) нужен только для автоматического сбора
   классических данных; для просмотра отчётов он не требуется.

## Еженедельный ритуал

Цель — получить из кабинетов короткий список тем для контент-плана. Яндекс обновляет данные
раз в неделю, поэтому недельный ритм разумен.

1. **Откройте или выгрузите списки.** Bing: Top Opportunity Queries и Your Grounding Queries.
   Яндекс: примеры запросов и страницы. Google: страницы с показами в AI-ответах.
   Если выгрузки нет (см. «не подтверждено» выше) — перепишите запросы в таблицу руками.
2. **Выберите пробелы.** Запрос — пробел, если выполняется любое из четырёх условий:
   - это запрос из **Top Opportunity Queries** Bing;
   - это пример запроса в отчёте Яндекса, где **цитируют не вас**;
   - в обычной выдаче вы на **позициях 4–15** («почти топ» — действующее правило из
     [`CONTENT.md`](CONTENT.md));
   - у запроса **много показов, но подходящей страницы на сайте нет**.

   Брендовые запросы (названия чужих компаний) отбросьте.
3. **Сгруппируйте по намерению.** Намерение — что человек хочет получить. Ни один из
   инструментов не даёт готовых меток, поэтому разложите сами по простой таблице:
   «как сделать», «что такое», «сравнение», «цена / купить», «установка», «бренд».
4. **Присоедините соседние запросы.** К каждому пробелу припишите запросы, где вы **уже
   есть**: из той же темы (Topic в Topics Portfolio) или с общими словами. Они подсказывают,
   какой странице нужен соседний материал и что ей перелинковать.
5. **Решите, что делать.** Если на сайте уже есть страница по теме и она ранжируется — **«усилить
   существующий»** (добавить раздел, FAQ, обновить заголовок; адрес не менять). Если
   страницы нет — **«новый материал»**.
6. **Передайте в M0.** Строка пробела плюс её соседние запросы — это список целевых запросов
   для шага M0 в [`CONTENT-PIPELINE.md`](CONTENT-PIPELINE.md). Заголовок и FAQ строятся
   под них, по [формуле тайтла](CONTENT.md).

Удобная рабочая таблица:

| Запрос | Откуда | Намерение | Есть ли у нас страница | Соседние запросы, где мы есть | Действие |
|---|---|---|---|---|---|

## Доступ из скриптов

Сначала про автоматизацию: ни у одного из трёх AI-отчётов **нет документированного API**.
Классические данные о запросах (позиции, показы, клики) API отдают.

| Инструмент | Отчёт про AI-ответы | Классические данные о запросах |
|---|---|---|
| Bing | Нет в документированном API (список методов `IWebmasterApi`, документация обновлялась в 2023). Только интерфейс | Методы `GetQueryStats`, `GetPageStats`, `GetQueryPageStats`, `GetRankAndTrafficStats`, `GetRelatedKeywords`. Доступ по API-ключу (один на пользователя) или OAuth 2.0 |
| Google | В публикациях и справочнике API значения для отчётов Generative AI не найдено (**не подтверждено**). Интерфейс | Search Analytics API, метод `searchanalytics.query`: разрезы `query` и `page`, до 25 000 строк за вызов, доступ `webmasters.readonly` |
| Яндекс | API для отчёта про Алису в документации не упомянут. Интерфейс | API v4 с OAuth: `search-queries/popular` (топ-3000 запросов за последнюю неделю, по 500 за вызов) и `query-analytics/list` (последние две недели; больше 10 000 запросов в час на домен — ответ 429 и временная блокировка). Есть бета-API аналитики по URL: 100 запросов в день бесплатно, 500 тыс. в месяц — платный тариф |

Лимиты и цены не проверены: у Bing в открытых страницах они не указаны, квоты Google и цена
расширенного тарифа Яндекса не открывались — **не подтверждено**.

**Запасной путь для всех трёх AI-отчётов:** раз в неделю человек скачивает выгрузку (или, если
кнопки нет, копирует таблицу в CSV) и кладёт файл в папку «входящие». Формат выгрузок не
документирован и может измениться, поэтому разбор должен падать с ошибкой, а не молча
терять строки.

> **Запланировано, в репозитории пока нет.** Команды сборщика данных `npm run
> visibility:collect` (забирает данные по API и разбирает выгрузки из папки «входящие») и
> `npm run visibility:gaps` (находит пробелы по четырём правилам выше и собирает список по
> намерениям) — только в планах. Сейчас в `package.json` их нет, примеров запуска нет:
> весь ритуал выше выполняется руками.
