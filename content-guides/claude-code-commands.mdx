# Команды Claude Code 2026, которые экономят часы

Большая часть времени в Claude Code теряется не на сложных задачах, а на рутине: перечитывании контекста, повторных объяснениях, ручном ревью. Половину этого закрывают встроенные команды – их просто мало кто знает.

Ниже – команды и приёмы, которые реально экономят часы. К каждой: что делает и когда применять. Команды набираются прямо в сессии. Наберите `/` – Claude Code покажет доступные и отфильтрует по буквам.

## Старт сессии: /init, /clear, /resume

Первое, что определяет качество работы, – чистый старт.

- `/init` – анализирует кодбазу и генерирует стартовый `CLAUDE.md`: структуру, ключевые файлы, конвенции. Первый шаг в новом репозитории. Без этого Claude каждый раз заново разбирается, что у вас за проект.
- `/clear` – очищает контекст и начинает новый разговор. Файлы проекта и `CLAUDE.md` остаются. Применяйте между несвязанными задачами – иначе старый контекст тянется и сбивает модель.
- `/resume` – возвращает к предыдущей сессии по списку или имени. Удобно, когда переключаетесь между параллельными задачами и не хотите терять нить.

:::tip Совет
Стандартный заход в новый проект: `/init` → поправить сгенерированный `CLAUDE.md` под себя → работать. 30 секунд, которые окупаются всю сессию.
:::

## Контекст под контролем: /compact, /context, /usage

Главная причина, по которой Claude начинает «тупить» в длинной сессии, – переполненный контекст. Три команды держат его в форме.

- `/compact` – сжимает историю разговора в краткое саммари и освобождает контекст. `CLAUDE.md` и правила остаются. Можно добавить инструкцию, что сохранить: `/compact оставь детали по API`. Запускайте проактивно в долгой сессии, не дожидаясь предела.
- `/context` – показывает, чем занят контекст: какие файлы, история, инструменты съедают токены. Первый шаг, когда непонятно, почему контекст быстро забивается.
- `/usage` (псевдоним `/cost`) – расход токенов и лимиты вашего плана за сессию. Команда, которую стоит держать под рукой на платных тарифах – сразу видно, что жрёт лимит.

:::warning Важно
Если упёрлись в лимит – не перезапускайте сессию вслепую. Сначала `/context`, чтобы увидеть пожирателей контекста, потом `/compact`. Перезапуск теряет наработанный контекст, сжатие – нет.
:::

## Модель и глубина мышления: /model, /effort, ultrathink

Одна и та же задача может стоить в разы дешевле или дороже – зависит от модели и уровня рассуждений.

- `/model` – переключает активную модель прямо в сессии. Сильную модель – на архитектуру и сложную логику, экономную – на массовую работу субагентов.
- `/effort` – задаёт уровень рассуждений: `low`, `medium`, `high`, `max`. `low` дешевле и быстрее на простом, `max` – максимум глубины на трудном. Реальный рычаг «цена против интеллекта».
- `ultrathink` – ключевое слово прямо в промпте. Добавьте его в текст запроса – и Claude рассуждает глубже на этот ход. Это не отдельная команда и не режим: просто слово в промпте, которое модель распознаёт.

:::tip Совет
`think`, `think hard` и подобные фразы – это просто текст, они ничего не включают. Реально на глубину влияют `/effort` и ключевое слово `ultrathink`.
:::

## Ревью и качество: /review

Claude Code умеет ревьюить собственный и чужой код – это снимает с вас механическую вычитку.

- `/review` – автоматическое ревью изменений или pull request: ищет баги и проблемы корректности.
- `/code-review` – более глубокое ревью диффа с уровнями (от лёгкого до максимального) и флагом `--fix`, который сразу применяет правки. Удобно перед коммитом.
- `/security-review` – проверяет изменения на уязвимости: инъекции, проблемы с авторизацией, утечки данных. Запускайте перед выкаткой в прод.

## Агенты и MCP: /agents, /mcp

Две команды, которые превращают Claude Code из одного ассистента в управляемую систему.

- `/agents` – управление субагентами: роли, настройки. Так собирается связка «оркестратор → специалисты» (исследователь, кодер, ревьюер). Один субагент – одна задача, основной контекст остаётся чистым.
- `/mcp` – подключение MCP-серверов: внешние инструменты и источники данных (база, API, поиск). Периодически проверяйте их – плохо написанный MCP может незаметно раздувать расход токенов.

## Память: символ # и /memory

Самый недооценённый приём – фиксировать правила прямо по ходу работы.

- `#` – наберите `#` и инструкцию, и Claude Code добавит её строкой в `CLAUDE.md`, не прерывая сессию. Поймали повторяющуюся ошибку – зафиксировали правило: `# всегда запускай npm test перед коммитом`. В следующих сессиях это уже учтено.
- `/memory` – открыть и отредактировать файлы памяти (`CLAUDE.md`), посмотреть, что загружено.

Подробно про устройство `CLAUDE.md` – в [отдельном гайде по памяти и правилам Claude Code](/guides/claudemd-guide/).

## Горячие клавиши, которые экономят минуты

Не всё – слэш-команды. Часть приёмов живёт на клавиатуре.

| Приём | Что делает |
|-------|-----------|
| `Shift+Tab` | Переключает режимы: обычный → авто-правки → plan-режим. Быстрый способ уйти от «спрашивать на каждый шаг» к работе без трения |
| `Esc` | Прерывает ответ на середине, сохраняя сделанное |
| `Esc` `Esc` | Откат: возврат разговора и кода к предыдущей точке |
| `@` | Упоминание файла: `@src/api.ts` – Claude подставит файл в контекст |
| `!` | Shell-режим: `! npm test` выполнит команду напрямую, без интерпретации |
| `Ctrl+O` | Транскрипт – детальный вывод инструментов и вызовов MCP |

Откат также доступен командой `/rewind`, а plan-режим – командой `/plan`.

## Свои команды

Когда повторяете один и тот же промпт – превратите его в команду. Сейчас для этого два пути.

Современный – скилл. Папка `.claude/skills/имя/SKILL.md` (проектный уровень) или `~/.claude/skills/имя/` (для всех проектов) даёт команду `/имя`. Скилл может нести с собой шаблоны, скрипты и доки – это рекомендованный способ для новых наработок. Готовые наработки удобно брать из библиотек [бесплатных скиллов для Claude Code](/guides/claude-code-skills/), а не писать с нуля.

Простой – одиночный файл. Файл `.claude/commands/имя.md` тоже создаёт команду `/имя`. Это легаси, но всё ещё работает – удобно, когда нужен один короткий промпт без обвязки. Аргументы доступны через `$ARGUMENTS`:

```markdown
---
description: Сгенерировать тесты для файла
---

Напиши тесты для: $ARGUMENTS
```

Дальше вызываете `/имя src/api.ts`. Так личная библиотека промптов заменяется набором команд – и приёмы перестают теряться.

## План на каждый день

Команды работают не по отдельности, а в связке. Рабочий цикл:

1. `/init` в новом проекте, поправить `CLAUDE.md`.

2. Plan-режим (`Shift+Tab` или `/plan`) для задач сложнее трёх шагов.

3. `/compact` и `/context`, когда сессия длинная.

4. `/review` перед коммитом, `/security-review` перед прод.

5. `#` – каждый раз, когда поймали ошибку, фиксируете правило.

Разница между новичком и опытным пользователем – почти целиком в этой системе, а не в качестве отдельных промптов.

## FAQ

### Какие основные команды есть в Claude Code?
Команды для старта сессии, контроля контекста (/context, /compact), переключения модели, ревью кода и накопления памяти. В гайде к каждой — короткое «что делает» и «когда применять».

### Как переключить модель в Claude Code?
Прямо в сессии командой выбора модели — можно гонять Opus на сложном и более лёгкую модель на простом, не перезапуская агента.
