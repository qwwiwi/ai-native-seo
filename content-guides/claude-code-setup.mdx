# Claude Code setup 2026: официальный плагин, который сам настроит проект

Новичок ставит Claude Code и застревает на одном вопросе: а что теперь подключать? Хуки, скиллы, MCP-серверы, субагенты – список расширений большой, а какие из них нужны именно твоему проекту, непонятно. В 2026 у Anthropic на это есть официальный ответ – система плагинов с маркетплейсом и плагин `claude-code-setup`, который сам сканирует твой код и подсказывает.

Прямой ответ: подключи официальный маркетплейс командой `/plugin marketplace add anthropics/claude-plugins-official`, поставь плагин `/plugin install claude-code-setup@claude-plugins-official`, а потом просто попроси «порекомендуй автоматизации для этого проекта». Плагин просканирует папку и выдаст 1-2 лучшие рекомендации в каждой категории – хуки, скиллы, MCP, субагенты, слэш-команды. Ничего в файлах он не меняет, только советует.

## Что такое плагины Claude Code

Плагин – это упаковка расширений Claude Code в один устанавливаемый пакет. Внутри одного плагина могут лежать сразу несколько типов автоматизаций:

- **Скиллы** – упакованная экспертиза и повторяемые задачи (вызываются как `/имя-плагина:имя-скилла`).
- **Субагенты** – специализированные помощники (ревьюеры по безопасности, производительности), появляются в `/agents`.
- **Хуки** – автодействия на событиях (автоформат, автолинт, блокировка правок чувствительных файлов).
- **MCP-серверы** – внешние интеграции (базы данных, браузер, документация) через `.mcp.json`.
- **Слэш-команды** – быстрые рабочие процессы вроде `/test` или `/pr-review`.

Раньше всё это подключалось вручную по одному. Плагин собирает набор в один пакет, а **маркетплейс** – это каталог таких плагинов, откуда их ставят одной командой. У Anthropic есть свой официальный маркетплейс – репозиторий `anthropics/claude-plugins-official`, «официальный, управляемый Anthropic каталог качественных плагинов Claude Code».

Если сначала нужно поднять сам Claude Code, у нас есть отдельный разбор – [как установить Claude Code с нуля](/guides/kak-ustanovit-claude-code/). Дальше идём от рабочего терминала. Если Claude Code для вас в новинку — начните с [обзора инструмента](/claude-code/).

## Что делает плагин claude-code-setup

`claude-code-setup` – официальный плагин Anthropic (автор в манифесте – Anthropic). Внутри него один скилл – `claude-automation-recommender`. Его работа: просканировать твой проект и выдать точечные рекомендации по настройке Claude Code под конкретно этот стек.

Он смотрит на признаки проекта – манифесты (`package.json`, `pyproject.toml`, `Cargo.toml`, `go.mod`), зависимости (React, Next.js, Express, FastAPI, Django, Prisma, Supabase, Stripe), структуру папок (`src/`, `app/`, `tests/`, `components/`, `api/`), наличие тестов и CI, уже существующий `CLAUDE.md` или папку `.claude/` – и по этим сигналам подбирает автоматизации. Логика простая: каждый сигнал ведёт к своей рекомендации. Увидел популярные библиотеки – советует MCP-сервер context7 для живой документации; фронтенд с UI-тестами – Playwright MCP; Supabase – Supabase MCP; репозиторий на GitHub – GitHub MCP для issues и PR; тесты (Jest, pytest) – хук на автолинт и субагента-ревьюера. Он не ограничен зашитыми списками: по нестандартным инструментам плагин добирает рекомендации веб-поиском, чтобы попасть именно в твой стек.

Ключевое: плагин **read-only**. Он анализирует и выдаёт список рекомендаций, но сам ничего не создаёт и не правит в проекте. Внедряешь ты – руками или отдельной просьбой к Claude. Это безопасно запускать на любом проекте: он не тронет ни один файл.

## Шаг 1: подключи официальный маркетплейс

Открой терминал в папке проекта, запусти `claude` и внутри сессии выполни:

```bash
/plugin marketplace add anthropics/claude-plugins-official
```

Команда `/plugin marketplace add` добавляет каталог плагинов. Источником может быть репозиторий GitHub в формате `владелец/репо` (как здесь), git-URL или локальный путь. После этого маркетплейс появится в менеджере плагинов – его видно на вкладке «Marketplaces» в интерфейсе `/plugin`.

## Шаг 2: установи плагин claude-code-setup

Из подключённого маркетплейса ставим сам плагин:

```bash
/plugin install claude-code-setup@claude-plugins-official
```

Формат `имя-плагина@имя-маркетплейса` – так Claude Code понимает, откуда брать плагин. Установка занимает секунды. Проверить, что плагин встал, можно командой `/plugin` – открой вкладку «Installed», там должен быть `claude-code-setup`. Если нужно применить изменения без перезапуска сессии – выполни `/reload-plugins`.

## Шаг 3: запусти сканирование проекта

Теперь просто попроси Claude Code – обычным языком, никакой специальной команды не нужно:

```text
порекомендуй автоматизации для этого проекта
```

Другие рабочие формулировки, которые триггерят скилл: «помоги настроить Claude Code», «какие хуки мне использовать?». Плагин просканирует папку и выдаст топ 1-2 рекомендации в каждой категории: MCP-серверы, скиллы, хуки, субагенты, слэш-команды. Если хочешь больше вариантов по одному типу – попроси прямо: «дай больше рекомендаций по MCP-серверам», и получишь 3-5 штук.

## Шаг 4: внедри то, что подошло

Рекомендации – это список, дальше решаешь ты. Плагин ничего не поставил сам, поэтому нужное подключаешь отдельно. Самый простой путь – попросить Claude Code тут же: «поставь хук на автоформат», «подключи context7 MCP», «создай субагента-ревьюера по безопасности». Он сделает это в текущей сессии.

Скиллы из рекомендаций ставятся своей командой – если не знаешь, куда они попадают и как проверить результат, у нас есть пошаговый разбор [установки скилла в Claude Code](/guides/claude-code-skills-install/). Начни с 1-2 автоматизаций, которые реально закрывают твою боль на этом проекте, а не со всего списка сразу – так настройка не превратится в свалку.

## Ставим плагин без интерактива

Если хочешь, чтобы плагин включался автоматически на старте (например, на всех своих проектах или в команде), пропиши его в `settings.json`. За плагины отвечают два ключа:

- `extraKnownMarketplaces` – добавляет маркетплейсы, которые Claude Code должен знать (аналог `/plugin marketplace add`, но в конфиге).
- `enabledPlugins` – список плагинов, которые включаются автоматически при запуске сессии.

`settings.json` живёт в трёх местах: пользовательский `~/.claude/settings.json` (глобально для тебя), проектный `.claude/settings.json` (коммитится в репозиторий, действует для всей команды) и локальный `.claude/settings.local.json` (личные правки, не в гит). Пропиши маркетплейс и плагин в проектный `settings.json`, закоммить – и у каждого, кто откроет проект, `claude-code-setup` подключится сам, без ручных команд в каждой сессии. Это и есть суть подхода: конфигурация Claude Code как код, а не набор кликов, которые каждый повторяет вручную.

## FAQ

### Нужна ли отдельная подписка, чтобы ставить плагины Claude Code?
Нет. Плагины и маркетплейс – встроенный механизм Claude Code, отдельного тарифа за них не берут. Нужен только рабочий Claude Code – с любой подпиской Claude (Pro или Max) или с API-ключом.

### Плагин claude-code-setup изменит мой код?
Нет. Скилл внутри плагина read-only – он только анализирует проект и выдаёт рекомендации, но сам не создаёт и не правит ни одного файла. Внедряешь рекомендации ты сам или отдельной просьбой к Claude.

### Официальный ли это плагин или чей-то самопал?
Официальный. Автор в манифесте плагина – Anthropic, и лежит он в официальном маркетплейсе `anthropics/claude-plugins-official`. На GitHub есть много похоже названных репозиториев вроде `my-claude-code-setup` – это личные конфиги отдельных людей, не путай их с официальным плагином из маркетплейса Anthropic.

### Что именно рекомендует плагин?
Топ 1-2 автоматизации в каждой из категорий: MCP-серверы (внешние интеграции – документация, браузер, база данных), скиллы, хуки (автодействия вроде автоформата и линта), субагенты (специализированные ревьюеры) и слэш-команды. Рекомендации подбираются под твой стек – по зависимостям, структуре и инструментам проекта.

### Как удалить плагин, если он больше не нужен?
Командой `/plugin uninstall claude-code-setup@claude-plugins-official`. Временно выключить без удаления – `/plugin disable claude-code-setup@claude-plugins-official`, а вернуть – `/plugin enable ...`.
